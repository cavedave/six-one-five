## (9,2,8) — 4200 candidate shapes, 0 cls5_shaped

Enumerator uses **8 slots** (larger side). Top shapes have **2 PAIR + 4 FREE + 1 UNIT + 1 FIXED** — huge free grid (~10²⁴ at B=10⁶) but **P4=n, P5=n** because there is no single `B^k` anchor and no `--S` scale supplied.

**Takeaway:** architecturally promising (find2 + many free peels), but the tool cannot certify production readiness without a **reduction / master modulus** for the 9th-power two-vs-eight identity. Next step is number theory, not more enumeration.

## (6,6,6) — 240 candidate shapes, 0 cls5_shaped

Top shapes: **2 PAIR + 3 FREE + 1 UNIT** on 6 slots. Same blocker: **P4=n** (balanced 6=6 side, no `B^k` + no S).

**Takeaway:** symmetric equal-count identities need a different modeling pass (which side is “RHS”, what is UNIT, what scale S). The current enumerator assumes one side is a single anchor (`n=1` or explicit S).
